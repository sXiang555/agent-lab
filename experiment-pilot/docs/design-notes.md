# 从跑分差值到可复现的实验复盘

复盘最容易出错的一步是把两条 AP 直接相减。示例里，DET-003 的 AP 比基线高 2.8 点，但它换了验证集划分。页面先展示口径不一致，右侧引用两条运行记录。实验员可以按基线的数据、训练、评估和 seed 口径申请补跑。

`compare_runs(baseline, candidate)` 接收两条已登记的运行记录，返回状态、原因和可选的 AP 点差值。同一轮状态按 `triage → collect → draft → verify` 前进。规则计算出的差值由结果卡片直接呈现。模型从与本轮状态匹配的动作中选一项，建议内容和引用由服务端固定生成。单次同 seed 差值描述这对运行，估计模块收益还需要多 seed 的成对复跑。

审批记录包含目标代码版本和基线口径，使用同一轮次生成稳定申请 ID。`interrupt()` 只暂停工作流。API 先验证审批员和项目，再通过 `Command(resume=...)` 恢复。状态条件更新和队列插入在同一个数据库事务内。客户端用同一请求 ID 重试，审批决策在重启后也可恢复。

手册按小标题切块。BM25 保留 AP、seed 和运行编号一类字面线索，向量通路提供另一套排序，RRF 融合两路名次。默认规则演示用确定性 hash 向量和标题重排，另支持远程 embedding 与重排模型。真实数据可以另做对照，分别比较纯 BM25、融合以及融合加重排的结果。

当前离线集有 20 个场景、100 个问法，覆盖正负差值、不同划分和种子、证据缺失、查手册与申请审批。基线 JSON 保存每条用例的断言、节点轨迹和耗时。测试集中固定资料较少，延迟也来自本机离线路径。接入实际模型后，需要单独记录检索召回、模型评审与人工抽检一致率、服务延迟和成本。

演示录屏依次展示可比的 AP 对照、不同划分触发的补跑申请、审批和入队。面试演示时可打开证据面板解释差值来源，再补充一例拒绝访问隔离项目运行的测试。

第一轮本地模型评测的规则断言全部通过，但人工抽查发现，模型曾对单次对照给出“并未显著影响”的自由文本建议。最终实现改为选择受控动作，例如在数据划分变化时对齐训练条件，在同 seed 对照后建议做多 seed 配对验证。规则断言仍能保护 AP 数值，动作白名单额外约束了解释范围。
